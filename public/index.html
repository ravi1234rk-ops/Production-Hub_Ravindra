Quality & first-time-right

FTR = verified first-pass deliveries ÷ deliveries with a verified first-pass decision. A project Build, each identified CR and each bulletin CR (by QA task) count once, not once per executor or defect. Published Design QA bulletin reports are considered verified: no additional validation is required. Reported bugs count as FTR failures; manual corrections remain available. Other teams need confirmed QA. Work without a QA decision is excluded from the percentage, never assumed passed.

Approved scoring and evidence rules

Productivity compares completed assets with the highest count in the same team/role: ≥90% = 30, ≥85% = 24, ≥70% = 18, ≥40% = 12, below 40% = 6. No benchmark means Not verified. Auditor productivity uses completed Asset Audit tasks. Utilization shows productive hours against 150h/month separately, not an invented score.

Quality misses per quarter: 0–2 = 30, 3 = 25, 4 = 15, 5+ = 0. On-time delivery: more than 1 miss = 0, otherwise 10. Process misses: below 5 = 10, 5–10 = 5, above 10 = 0. Manager feedback: four Met/Not met criteria worth 5 points each. Missing evidence needs Manager verification. A changed evidence set makes a confirmed review stale.

Ratings: Manager 17–20 / 13–16 / 9–12 / 5–8 / 0–4 → 5 / 4 / 3 / 2 / 1. Productivity 25–30 / 19–24 / 13–18 / 7–12 / 0–6 → 5 / 4 / 3 / 2 / 1. Quality 0–2 / 3 / 4 / 5 / 6+ misses → 5 / 4 / 3 / 2 / 1. Final overall rating remains Manager-reviewed; no unapproved conversion from total /100.
